# Metrics - Speed Milestone: First Four Performance Fixes

Full analysis: `claude/reports/report_8_20260831-172937.md`. Baseline for comparison:
`claude/reports/report_7_20260831-160005.md`.

**This is a speed milestone, not an accuracy one.** The 45-prompt scored suite
(`claude/test_cases/`) was not re-run, so the headline accuracy numbers in `timeline.md` are
carried forward unchanged from `metrics_5` rather than re-measured. They must not be read as
confirmed at this milestone.

## Scope

The 20-prompt hard set (`data/input/function_calling_tests.json.bak`, identical to `HEAD`), the
same input the report-7 baseline profiled. Not the 11-prompt set currently in the working tree.

| Metric | Baseline | Now | Change |
|---|---|---|---|
| Wall clock, 20 prompts | ~15 min (extrapolated from 11) | **9:51.85** | |
| Seconds per forward pass | 1.986 | **1.795** | -9.6% |
| Forward passes per completion | 6.53 | **5.60** | -14% |
| Wasted forward passes | 38 of 248 (15.3%) | **0 of 325** | eliminated |
| Name selection, per prompt | 8.80 s | **2.88 s** | **3.05x faster** |
| Parameter generation, per prompt | 33.72 s | **28.02 s** | 1.20x faster |
| Share of runtime in the model | 99.0% | 99.0% | unchanged |
| Max RSS | not measured | 5.23 GB | |

Seconds-per-prompt went 45.2 -> 30.9, but the two runs cover different prompt subsets (0-10 versus
0-19), so that pair is not apples-to-apples and is excluded from the table above on purpose.

## What this bought

All four fixes landed and are individually verified in report 8. Name selection is now 9.3% of the
run and effectively solved. **90.7% of the remaining time is parameter generation**, where the
forward-pass count is already near its floor (7.3 passes per parameter) and the cost is almost
entirely prompt length: 408 tokens of fixed template on every one of 285 forward passes, at a
measured 3.47 ms per token per pass.

Still over the subject's 5-minute budget at 9:51. Closing the gap needs the parameter template cut
to roughly 200 tokens (header halved, down to one few-shot example), which is the first change in
this sequence that can move accuracy and therefore the first that requires re-scoring.

## Accuracy note

Not scored, but one visible defect in the 20 outputs: prompt 9 ("Tell my mom I'll be home in 42
minutes...") returned `recipient: "John \"The Rock\" Doe"`, copied verbatim out of few-shot
example 2. Few-shot contamination. No before-picture exists (the baseline log was overwritten), so
this is not established as a regression. It is direct evidence that the current few-shot set is
harmful as well as expensive, which bears on the trimming work that comes next.

The other 19 outputs are correct, including both large-integer sums, both scientific-notation
cases, `--42`, the escaped-quote names, `fn_book_flight`'s five mixed-type parameters, and the
prompt-injection refusal.
