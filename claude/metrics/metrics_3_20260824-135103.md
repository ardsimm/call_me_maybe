# Metrics — Per-Parameter Overflow Fallback (Revised `Infinity` Fix)

Full report: `claude/reports/report_5_20260824-135103.md`. Same scope as `metrics_2`: 5 scenarios,
45 scoreable prompts / up to 102 parameters.

| Metric | Result |
|---|---|
| Function name accuracy | 44/45 = **98%** (up from 96%) |
| Parameter accuracy | 99/102 = **97%** (down from 99%) |

The `Infinity`-overflow fix was revised: instead of aborting the whole prompt when a numeric
parameter overflows, only that one parameter now falls back to a placeholder while the function
name and every other parameter still come through normally. This recovers the function-name point
lost in the previous revision (a caller still gets a function to call) at the cost of the
parameter-accuracy point gained by full refusal (the still-wrong placeholder values count against
the tally again once the prompt counts as "function correct"). Net: same numbers as the very first
run of the expanded suite (`metrics_2`'s "first run" row), except now with a correctly-typed,
valid-JSON placeholder instead of the original `Infinity` corruption. Two implementation bugs
caught and fixed in the same pass: the float/bool overflow fallback was putting a string into a
field the schema declares numeric/boolean, and the `INT` branch had no fallback assignment at all
(latent risk of a stale cross-parameter value or a crash, though unreachable in practice since
`generate_parameters` already validates ints upstream).
