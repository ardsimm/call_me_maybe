# `accelerate` is a declared dependency, is a HuggingFace package, and is never used

`pyproject.toml` lists it under `[project].dependencies`:

```toml
dependencies = [
    "accelerate>=1.14.0",
    ...
]
```

It is imported nowhere in the repository:

```
$ grep -rn "accelerate" src/ tests/ llm_sdk/
(no output)
```

## Why this matters

`accelerate` is published by Hugging Face. The subject forbids "the huggingface package"
(IV.3.1), and unlike the `torch` import in issue #7 -- which at least has an innocent
explanation -- this one cannot be defended on any grounds, because nothing in the project uses
it. It is the second grep-visible hit a reviewer finds, and it is dead weight in the lockfile
either way.

It was most likely added while debugging model loading: `transformers` suggests installing
`accelerate` when `device_map="auto"` is passed, which `Small_LLM_Model.__init__` does on CUDA.
But that is `llm_sdk`'s dependency to declare, not this project's -- and `llm_sdk/pyproject.toml`
already declares `torch`, `transformers` and `huggingface-hub` for exactly that reason.

Verify before removing that model loading on CUDA still works without it, since the
`device_map="auto"` path is the one that wanted it:

```sh
uv run python -m src --output data/output/smoke.json
```

## Related: dev tooling is in the runtime dependency list

The same list carries `black>=26.5.1`, `flake8>=7.3.0` and `mypy>=2.2.0`. These are not a rule
violation -- `make lint` and `make black` need them, and the subject only says the reviewer runs
`uv sync` -- but they belong in a dev group so the runtime install stays lean:

```toml
[project]
dependencies = ["llm-sdk", "numpy<=2.4.6", "pydantic>=2.13.4"]

[dependency-groups]
dev = ["black>=26.5.1", "flake8>=7.3.0", "mypy>=2.2.0"]
```

`uv sync` installs dev groups by default, so `make lint` keeps working unchanged.

Keep `numpy` even though nothing imports it: the subject explicitly instructs "install the
packages numpy and pydantic using uv" (IV.3.1), so its presence is compliance, not bloat.
