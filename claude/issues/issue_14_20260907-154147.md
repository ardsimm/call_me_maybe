# Circular import: `import src.model` fails, and `python -m src` only works by import-order accident

```
$ uv run python -c "import src.model"
ImportError: cannot import name 'Model' from partially initialized module
'src.model' (most likely due to a circular import)
```

Four of six entry points into the package fail on a bare import:

| Import | Result |
|---|---|
| `import src.model` | ImportError |
| `import src.state` | ImportError |
| `import src.trie.trie` | ImportError |
| `import src.tokenize` | ImportError |
| `import src.generate` | OK |
| `import src.call_me_maybe` | OK |

## The cycle

```
src/model/model.py:6      from src.generate.generator_exceptions import FatalGenerationError
  -> executes src/generate/__init__.py       (importing a submodule runs the package __init__)
src/generate/__init__.py:1  from .generator_factory import GeneratorFactory
src/generate/generator_factory.py:2  from .generator import Generator
src/generate/generator.py:2  from src.model import Model
  -> src.model is still half-initialised    -> ImportError
```

The key step is the second line: `from src.generate.generator_exceptions import X` cannot avoid
executing `src/generate/__init__.py` first, and that `__init__` reaches all the way back into
`src.model`.

`python -m src` works only because `src/__main__.py` imports `src.call_me_maybe`, which imports
`src.generate` on line 5 -- before `src.model` on line 8. Reorder those two imports and the
program stops starting. It is working by accident.

## Why it matters beyond tidiness

Subject VIII, Submission and peer review:

> "During the evaluation, a brief modification of the project may occasionally be requested. This
> could involve a minor behaviour change, a few lines of code to write or rewrite, or an
> easy-to-add feature."

The obvious first move when asked to demonstrate or tweak anything is to open a REPL and type
`from src.model import Model`, or to write a two-line script that pokes at the trie. Both fail
immediately with an error that looks like the project is broken, and debugging an import cycle
under time pressure in front of a reviewer is not where you want to spend those minutes.

It also blocks any future unit test that imports a module directly rather than going through
`src.call_me_maybe`.

## Fix

Break the cycle at its weakest link: the exceptions. `GenerationError` and `FatalGenerationError`
are plain `Exception` subclasses that depend on nothing, but they live inside `src.generate`,
which is the heaviest package in the tree. Move them somewhere with no imports of its own:

```
src/exceptions.py     <- GenerationError, FatalGenerationError (and nothing else)
```

Then `src/model/model.py`, `src/state/__trie_state.py` and `src/prompting/__templates.py` import
from `src.exceptions` instead, and none of them drags in `src.generate` any more.

Re-export from `src/generate/__init__.py` if the current import paths should keep working:

```python
from src.exceptions import GenerationError, FatalGenerationError
```

Add a regression check so it cannot come back -- this is cheap and catches the whole class of
problem:

```sh
for m in src.model src.state src.tokenize src.trie.trie src.generate src.call_me_maybe; do
    uv run python -c "import $m" || echo "FAILED: $m"
done
```
