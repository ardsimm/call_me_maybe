# A prompt whose generation fails contributes no output entry, so the array can be shorter than the input

`CallMeMaybe.__process_prompts` catches a per-prompt failure, logs it, and moves on:

```python
# src/call_me_maybe.py:370-375
try:
    item = cls.__process_prompt(prompt.prompt, context)
    items.append(item)
except GenerationError as err:
    print(f"Error while generating prompt {prompt}:\n{err}")
    continue
```

Note the `item` built with `"name": "[None]"` immediately above the `try` is dead -- it is
overwritten on success and discarded on failure, so the placeholder never reaches the output.

## The rule

> Subject V.4, Output File Format: "**For each prompt**, add a JSON object to this file."

A skipped prompt means `len(output) < len(prompts)`, which a checker comparing the two arrays
positionally would read as a mismatch. The README documents the behaviour honestly ("A prompt
whose generation fails is reported and skipped rather than aborting the batch, so it contributes
no entry and the output can be shorter than the input"), so this is a known deviation rather than
an oversight.

## Observed frequency: zero

Across every run in this audit -- the default batch, 8 scenarios, 68 prompts, plus ~17 ad hoc
adversarial probes -- **no prompt ever hit this path**. `GenerationError` is raised only when a
`TrieState` is handed a token outside the trie, which the constrainer's own masking makes
unreachable in practice, or when a generated name matches no function, which the trie prevents by
construction.

So the deviation is currently theoretical. That is worth knowing before spending effort on it,
and it is also worth saying out loud at a defense: the recovery path exists and is correct, it
just does not fire.

## The trade-off

Skipping is defensible and arguably better engineering than the alternatives:

- **Emit a placeholder** (`name` = first function, parameters filled with type defaults) satisfies
  the letter of V.4 but writes a confidently wrong answer, and issue #9 argues at length that a
  schema-invalid or fabricated entry is worse than a missing one.
- **Abort the batch** loses every good result over one bad prompt, which is plainly worse.

The one option that satisfies both V.4 and the schema rules is to make failures not happen --
which, per the frequency note above, is already effectively the case.

## Recommendation

Leave the behaviour, but make the decision explicit rather than incidental:

1. Keep the README's existing note (it is accurate).
2. Be ready to say at the defense *why* skipping beats fabricating -- the argument is strong.
3. Delete the dead placeholder `item` so the code does not imply an intent it does not carry out.

Only revisit if a checker is known to compare array lengths, in which case coordinate with issue
#9 -- both are about what to write when there is no honest answer, and they should be resolved
the same way.
