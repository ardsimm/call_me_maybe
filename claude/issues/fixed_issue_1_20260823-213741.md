# Unused code and logic left over from an abandoned dependency-injection pattern

Follow-up to noticing `IntStateStage` declares `PRE_FLOAT_POINT`/`FLOAT_POINT` members that are
never referenced (copy-pasted from `FloatStateStage`, not part of `IntState`'s `_stages`). Checked
the rest of the codebase for the same pattern — confirmed via grep for actual call sites, not just
reading.

## Checklist

- [x] **`IntStateStage.PRE_FLOAT_POINT`/`FLOAT_POINT` are unused enum members** --
      `src/state/__int_state.py`: only `INITIAL`, `DATA`, `TERMINAL` appear in `_stages`/
      `_stage_allowed_tokens`/`_stage_transition_tokens`; the other two are dead, copy-pasted from
      `FloatStateStage`.
- [x] **`Tokenizer.model` setter is dead code** -- `src/tokenize/tokenizer.py`. Its validation
      (`if model is None or not isinstance(model, Model): raise ValueError(...)`) never runs:
      grepping for `.model = `/`.tokenizer = ` across `src/` finds no assignment to a `Tokenizer`
      or `Generator` instance's `model`/`tokenizer` attribute anywhere. The getter is used
      everywhere (`self.model.encode(...)`); only the setter is orphaned.
- [x] **`Generator.model` setter is dead code** -- `src/generate/generator.py`, same shape as
      above.
- [x] **`Generator.tokenizer` setter is dead code** -- `src/generate/generator.py`, same shape as
      above.
- [x] **`TrieState` doesn't use the `State` base class's data model** (design smell, not literally
      dead code) -- `src/state/trie_state.py` never populates `_stages`/`_stage_allowed_tokens`/
      `_stage_transition_tokens`, since it overrides `get_allowed_tokens`/`update_last_token`
      entirely with its own trie-walking logic. It inherits from `State` mostly for the
      `_tokenizer` binding in `__init__`, not for the state-machine contract the base class exists
      to provide.

## Notes

All three dead setters share one likely root cause: leftover scaffolding from when the project
used constructor-injected dependencies, before the codebase settled on singleton access
(`Model.get_instance()`, `TokenizerFactory.get_instance()`) everywhere instead -- matches the
"global singleton sprawl instead of dependency injection" observation from the very first audit
(`claude/reports/report_0_20260823-193657.md`).

Checked and ruled out as false positives: every `FunctionNamesTemplates`/
`FunctionParametersTemplates`/`TemplateDirectories` enum member has a real call site;
`ParameterType.STRING` is an intentional fallthrough default, not dead; `Tokenizer.decode` is
called from `trie_state.py`, `__generator_impl.py`, and `__default_tokenizer.py`.

Separately, worth a mention though not quite "unused code": `returns` in
`functions_definition.json` is validated for presence/type in `Context.__init__` but its value is
discarded immediately after -- there is no `Function.returns` field at all. Likely intentional
(the app only ever decides a function's name and arguments, never executes it), so this reads as a
design characteristic rather than a bug -- flagging only because it's the same "validated then
thrown away" flavor as the rest of this issue.
