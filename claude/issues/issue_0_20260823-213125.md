# Exception-handling gaps: several failure paths bypass intended error handling

Full detail in `claude/reports/report_2_20260823-212921.md`. Found while writing docstrings'
`Raises` sections, which required tracing every call path's exceptions end to end rather than just
what each function raises itself.

Two of these (#1-#3 below) reproduce the exact "whole batch silently loses its output" shape as the
`TokenizerFactory` arity mismatch and `parameter.valie` typo bugs fixed earlier this session — just
triggered by different inputs.

## Checklist

*Final re-check 2026-08-24, after the user's own fixes -- every item below was re-tested against
the running program, not just read from source.*

- [x] **`Context.__init__` exceptions escape `run()`'s catch** -- **fixed.**
      The `functions_definition` file's `open()`/`json.loads()` is now wrapped in
      `except (OSError, json.JSONDecodeError) as err: raise ParsingError(...)`, and
      `Function`/`Parameter` construction now catches both `TypeError` (malformed per-parameter
      entry) and `ValueError` (bad `ParameterType`, and empty name/description via
      `pydantic.ValidationError`, itself a `ValueError` subclass) -- both converted to
      `ParsingError`. Verified live: a parameter type of `"array"` and a parameter entry that's a
      plain string instead of a dict both now produce a clean `"Parsing failed: ..."` message, not
      a traceback. One tiny residual asymmetry: the *second* file read in the same method
      (`arguments.input`, the prompts file) is still unwrapped at this layer -- but in practice this
      is masked, since `Arguments.validate_model` already opens and validates both files before
      `Context` is ever constructed, and any failure there is now caught either by the (also fixed)
      `DeserializationException` handling or `ArgumentParser.parse`'s pre-existing blanket
      `except Exception`. Verified live: both a missing prompts file and an invalid-JSON prompts
      file produce a clean message. Only a genuine TOCTOU race (file changes in the split second
      between `Arguments` validating it and `Context` re-reading it) could still hit the unwrapped
      path -- vanishingly unlikely, not worth chasing further.
- [x] **All-or-nothing batching** -- **exposure now effectively zero for known triggers.**
      `__process_prompts` still only catches `GenerationError` per prompt, same shape as before,
      so the structural gap technically remains. But every concrete trigger this issue originally
      cited is now handled *before* it would ever reach that boundary: numeric/boolean coercion
      failures are caught locally inside `__process_prompt` with placeholder fallbacks, and bad
      input data is now caught up front during `Context` construction (see above). No known live
      path left to actually exercise this.
- [x] **`main()` always exits 0, even on crash** -- **fixed and verified.** `src/__main__.py` now
      calls `sys.exit(1)` after printing the traceback. Confirmed with a synthetic forced crash
      (monkey-patched `CallMeMaybe.run` to raise): process exit code is `1`, not `0`.
- [x] **Boolean branch raises `ValueError` instead of `GenerationError`** -- fixed (see above); the
      branch no longer raises at all.
- [x] **`JSONAdapter.serialize`/`.parse` catch the wrong exception type** -- **fixed.**
      `serialize` now catches `TypeError` (what `json.dumps` actually raises on a non-serializable
      value), not the old, never-matching `json.JSONDecodeError`. `parse`'s `json.JSONDecodeError`
      catch was already correct for `json.loads` and is unchanged.
- [x] **`Arguments.validate_model` catches the wrong exception type** -- **fixed.** Now catches
      `DeserializationException` (what `JSONAdapter.parse` actually raises) instead of the dead
      `json.JSONDecodeError`. This fix briefly introduced a circular import (`arguments.py` importing
      `src.parsing.parser_exceptions` at module level, while `src.parsing.parser` imports `Arguments`
      back) -- resolved by moving that import into `validate_model`'s function body, a lazy import
      that only runs once every module has finished loading.
- [x] **`StateFactory.get_instance`'s `TRIE_STATE` branch is broken** -- **fixed.** The dead
      `if type == StateType.TRIE_STATE` branch (referencing a `StateType` member that never
      existed) has been removed entirely; the method now falls straight through to the intended
      `ValueError` for anything other than `STRING_STATE`/`INT_STATE`/`FLOAT_STATE`.
- [ ] **`SystemExit` from argparse bypasses the app's own error messaging** -- **accepted, won't
      fix.** Minor, and arguably the correct behavior for `--help` specifically.

## Summary

6 of 8 items fully fixed and verified live; 1 (all-or-nothing batching) is structurally unchanged
but has no remaining known trigger; 1 (`SystemExit`) is an accepted won't-fix. Full regression
suite (`claude/test_cases/`, 5 scenarios) re-run clean with no new crashes or misses, and
`make lint` (flake8) is clean.
