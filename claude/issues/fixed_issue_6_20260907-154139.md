# The project declares Python >=3.10 but needs 3.12+, so `uv sync` can produce a SyntaxError

`pyproject.toml` declares `requires-python = ">=3.10"`, the README's Prerequisites say
"Python 3.10+", and the subject (IV.1, General Rules) says "Your project must be written in
Python 3.10 or later". There is **no `.python-version` file**, so `uv` is free to build the venv
with any interpreter satisfying `>=3.10`.

If the reviewer's machine resolves that to 3.10 or 3.11, `uv run python -m src` never reaches
`main()` -- it dies while importing:

```
$ python3.10 -m py_compile src/call_me_maybe.py
SyntaxError: unterminated string literal (detected at line 264)

$ python3.11 -m py_compile src/state/__trie_state.py
SyntaxError: unterminated string literal (detected at line 78)
```

Verified against real CPython 3.10.12 (`/usr/bin/python3.10`) and real CPython 3.11.15
(installed via `uv python install 3.11`), not against `ast.parse(feature_version=...)`, which
does not model the tokenizer changes and reports a false pass.

Two independent version gates are in play.

## PEP 701 f-strings -- Python 3.12+ only

PEP 701 ("Syntactic formalization of f-strings", landed in 3.12) is what allows an f-string
replacement field to span multiple lines and to reuse the enclosing quote character. Three sites
rely on it:

| File | Line | Construct |
|---|---|---|
| `src/call_me_maybe.py` | 264-266 | replacement field split across three lines |
| `src/call_me_maybe.py` | 293 | `f"[{item["parameters"][parameter.name]}]"` -- `"` nested inside `"` |
| `src/state/__trie_state.py` | 78-80 | replacement field split across three lines |

```python
# src/call_me_maybe.py:264
                    print(f"Failed to generate float parameter {
                            parameter.name
                        }:", err.__str__())
```

## `enum.StrEnum` -- Python 3.11+ only

`StrEnum` was added in 3.11. Four classes depend on it:

```
src/models/context.py:1        from enum import StrEnum   -> ParameterType
src/prompting/__templates.py:1 from enum import StrEnum   -> TemplateDirectories,
                                                             FunctionNamesTemplates,
                                                             FunctionParametersTemplates
```

So the real floor is **3.12**, two minor versions above what is advertised in three places.

## Why this is the highest-priority item in the audit

The subject states that "The reviewer, as well as the moulinette, will just run `uv sync`"
(IV.3.1). Nothing else in this repository matters if `make run` opens with a traceback -- a
`SyntaxError` at import reads as a non-functional project, which the subject explicitly says is
a fail condition ("If your program crashes due to unhandled exceptions during the review, it
will be considered non-functional").

Note that `src/__main__.py`'s `try/except` cannot help here: it guards the *import* of
`src.call_me_maybe` against `KeyboardInterrupt` only, and a `SyntaxError` in an imported module
is raised at import time regardless.

## Fix

Two options. The first is strongly recommended.

**Option A -- tell the truth about the floor (2 lines, zero risk).**

```toml
# pyproject.toml
requires-python = ">=3.12"
```

```
# .python-version
3.12
```

The `.python-version` file is what makes this deterministic: without it, `uv` picks an
interpreter per machine, and `requires-python` alone only makes a wrong pick *fail to resolve*
rather than pin a right one. The README's Prerequisites line must move with it.

**Option B -- actually support 3.10.** Rewrite the three f-strings onto single lines with
alternating quote characters, and swap `StrEnum` for `class X(str, Enum)`. Then verify with
`python3.10 -m compileall src`, not by eye.

Whichever is chosen, add the check to the lint loop so it cannot regress silently:

```sh
uv run python -m compileall -q src
```

against the minimum supported interpreter.

## Checklist

- [ ] Decide the supported floor: 3.12 (Option A, recommended) or 3.10 (Option B).
- [ ] Update `requires-python` in `pyproject.toml` to match the decision, and `uv lock`.
- [ ] Add a `.python-version` file so `uv` pins deterministically instead of picking per machine.
- [ ] Update the README's "Prerequisites" section, which currently says "Python 3.10+".
- [ ] If Option B: rewrite `src/call_me_maybe.py:264-266`, `src/call_me_maybe.py:293` and
      `src/state/__trie_state.py:78-80` without PEP 701 syntax.
- [ ] If Option B: replace `StrEnum` with `class X(str, Enum)` in `src/models/context.py` and
      `src/prompting/__templates.py` (4 classes).
- [ ] Verify with a real interpreter of the minimum supported version, e.g.
      `uv python install 3.12 && $(uv python find 3.12) -m compileall -q src`.
- [ ] Consider adding that `compileall` check to the `lint` target so a future PEP 701 f-string
      cannot slip back in unnoticed.
