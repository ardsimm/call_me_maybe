# A 200 KB stdout log named `out` is committed at the repository root

```
$ git ls-files | grep '^out$'
out
$ wc -c out
200345 out
$ head -3 out
uv run python -m src
           _ _                                              _
  ___ __ _| | |    _ __ ___   ___     _ __ ___   __ _ _   _| |__   ___
```

It is a captured terminal session from a debugging run -- the full ASCII banner, every
`Generated:` line, every prompt separator.

## Why it got committed

`.gitignore` line 6 is:

```
.out
```

with a leading dot, which matches a file or directory *named* `.out`, not the file named `out`
that the profiling runs actually write. So the ignore rule has never matched anything and the
artifact went in unnoticed.

Issue #5's checklist already flagged the underlying habit -- "Give profile runs distinct output
filenames. The root `out` file holding the baseline profile was overwritten by a later run" --
so this is the same file, now also visible in git.

## Why it should go

Subject VIII lists exactly what the repository must contain:

> `src/`, `pyproject.toml` and `uv.lock`, `llm_sdk/`, `data/input/`, `README.md`, and "any
> additional files needed to run your solution".

A 200 KB terminal dump is none of those. It is also stale -- it predates several fixes, so
anyone reading it gets a picture of the program that no longer holds.

## Fix

```sh
git rm --cached out && rm out
```

and correct the ignore rule. `/out` anchors it to the repository root, which is where the runs
write it, and avoids accidentally ignoring a legitimately-named directory deeper in the tree:

```diff
-.out
+/out
```

While in `.gitignore`, note that the neighbouring entries are already correctly anchored
(`/data/output`, `/tests/output`, `/tests/stdout`, `/tests/stderr`, `/private`,
`/call_me_maybe`, `/run_tests`) -- `.out` is the odd one out, which is what makes the typo easy
to miss.

Better still, stop writing to a bare `out` at all. Redirect profiling and debugging runs into
`tests/stdout/` or a scratch directory that is already ignored, with a distinct filename per run
so a baseline cannot be overwritten by the next run (issue #5's open item).

## Checklist

- [ ] `git rm --cached out`, delete the local file.
- [ ] Change `.gitignore` line 6 from `.out` to `/out`.
- [ ] Verify with `git check-ignore -v out` that the rule now matches.
- [ ] Confirm nothing else stray is tracked:
      `git ls-files | grep -vE '^(src|tests|claude|data/input|templates|llm_sdk)/' `
- [ ] Adopt distinct, ignored filenames for profiling output so baselines are not overwritten
      (carried over from issue #5).
