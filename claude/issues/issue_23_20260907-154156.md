# The `lint` target adds `--exclude` flags the subject's command does not have

> Subject IV.2, Makefile: "**lint**: Execute the commands `flake8 .` and `mypy . --warn-return-any
> --warn-unused-ignores --ignore-missing-imports --disallow-untyped-defs --check-untyped-defs`"

The Makefile runs:

```make
flake8: install
	uv run python -m flake8 . --exclude=$(VENV),llm_sdk

mypy: install
	uv run python -m mypy . --warn-return-any --warn-unused-ignores \
	  --ignore-missing-imports --disallow-untyped-defs --check-untyped-defs \
	  --exclude $(VENV) --exclude tests
```

Three deviations, of clearly different weight.

## `--exclude .venv` -- keep it

Non-negotiable in practice. A bare `flake8 .` walks the virtualenv and reports thousands of
violations in third-party packages. Every submission that uses a venv does this. No reviewer will
object.

## `--exclude llm_sdk` -- keep it, and be ready to say why

`llm_sdk/` is provided by the subject and copied in verbatim ("To use `llm_sdk`, you can copy it
in the same directory as the one `src` is in"). Its code is not the project's work and linting it
is meaningless -- it also fails flake8 on line length. `pyproject.toml` already declares the mypy
side of this explicitly:

```toml
[[tool.mypy.overrides]]
module = "llm_sdk.*"
ignore_errors = true
```

Defensible, and worth a one-line comment in the Makefile so the reason is visible without asking.

## `--exclude tests` -- now removable

This is the one worth changing. It was masking two real mypy errors in `tests/__main__.py`
(`name_correct` rebound from `bool` to `int`). **Both were fixed during the audit**, so:

```
$ uv run python -m mypy . --warn-return-any --warn-unused-ignores \
    --ignore-missing-imports --disallow-untyped-defs --check-untyped-defs --exclude .venv
Success: no issues found in 49 source files
```

The exclusion no longer buys anything, and dropping it brings the command materially closer to the
subject's text while widening real coverage. Note `mypy --strict` over `tests/` has not been
verified -- `lint-strict` should keep `--exclude tests` unless that is checked too.

## Current status

Both targets pass as they stand:

```
$ make lint         -> Success: no issues found in 48 source files
$ make lint-strict  -> Success: no issues found in 48 source files
$ flake8 .          -> clean
```

There is no `setup.cfg`, `.flake8` or `tox.ini`, so flake8 runs on its defaults -- including the
79-column limit. Worth stating plainly at a defense: the code is compliant with stock flake8, not
with a loosened config.

## Checklist

- [ ] Drop `--exclude tests` from the `mypy` target now that `tests/` type-checks cleanly.
- [ ] Verify `mypy --strict` over `tests/` before dropping it from `mypy-strict` too; keep the
      exclusion there if it fails.
- [ ] Add a one-line comment in the Makefile explaining that `llm_sdk` is vendored from the
      subject and `.venv` is third-party.
- [ ] Confirm `make lint` and `make lint-strict` still pass after the change.
- [ ] Keep the absence of a flake8 config file deliberate -- default rules are a stronger claim
      than a tuned config.
